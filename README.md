# SHСклад — система управління складом

Повністю робочий вебдодаток на Google Apps Script + Google Sheets (база даних) +
Google Drive (фото). Працює в браузері на Windows, macOS, Android та iPhone (Safari) —
без встановлення застосунку.

## ⚠️ Важливе технічне уточнення

Google Apps Script дозволяє в проєкті лише файли `.gs` (сервер) та `.html` (клієнт) —
окремі `.css`/`.js` файли завантажити в редактор Apps Script неможливо. Тому:

- `style.css` → реалізовано як **`Style.html`** (вміст обгорнутий у `<style>...</style>`)
- `app.js` + `qr.js` → реалізовано як **`JavaScript.html`** (вміст обгорнутий у `<script>...</script>`,
  включає всю логіку SPA, складських операцій, Excel та сканування QR)

Ці файли підключаються в `index.html` через `<?!= include('Style'); ?>` та
`<?!= include('JavaScript'); ?>` — фінальний результат у браузері ідентичний
до того, якби це були окремі файли.

## Структура проєкту

```
Code.gs            — точка входу (doGet), спільні утиліти, доступ до Sheets/Drive
Setup.gs           — створення аркушів бази даних, стартові користувачі, міграція схеми
Auth.gs            — вхід, сесії (CacheService), перевірка ролей
Users.gs           — CRUD користувачів (тільки admin)
Products.gs        — CRUD товарів, пошук, приховування цін для не-адмінів
Warehouse.gs       — прихід / видача / переміщення / коригування залишків
History.gs         — незмінний журнал операцій
Drive.gs           — завантаження / видалення фото товарів у Google Drive
QR.gs              — генерація QR-кодів, масовий друк, пошук за QR
ImportExport.gs    — "розумний" імпорт/експорт Excel (розпізнавання колонок, дві ціни)
Assemblies.gs      — «Вироби»: BOM-специфікації, розрахунок собівартості, списання компонентів
Settings.gs        — одиниці виміру, статистика, сповіщення, резервні копії
appsscript.json    — маніфест проєкту (веб-застосунок, часовий пояс)

index.html         — каркас SPA (шапка, бічне меню, підключення партиалів)
login.html         — екран входу
dashboard.html     — дашборд/статистика
products.html      — список товарів + модалка друку QR
product.html       — картка товару (перегляд/редагування/операції/історія)
assemblies.html    — список виробів + редактор складу + запуск у роботу
history.html       — таблиця повної історії
settings.html      — користувачі, одиниці виміру, резервні копії (admin)
Style.html         — CSS (темна/світла тема, адаптивність)
JavaScript.html    — вся клієнтська логіка (app.js + qr.js)
```

## Нове: розумний імпорт Excel

Раніше імпорт вимагав точних заголовків колонок. Тепер сервер сам розпізнає
колонки за словником синонімів (`FIELD_SYNONYMS` у `ImportExport.gs`) —
незалежно від того, як вони названі у вашому файлі:

- **Артикул**: "Артикул", "Арт", "SKU", "Код", "Code"...
- **Назва**: "Назва", "Название", "Name", "Товар"...
- **Кількість**: "Залишок", "Кількість", "Остаток", "Qty"...
- **Ціни**: "Ціна місцевий", "Ціна Німеччина", "Цена1/2", "Local/German price"...
- **Фото**: "Фото", "Photo", "Image URL" — якщо у файлі є посилання на фото,
  воно підставиться в картку товару автоматично.

Якщо якусь колонку не вдалось розпізнати — вона просто ігнорується (не ламає
імпорт). Обов'язкові лише "Артикул" і "Назва" — без них рядок пропускається
з поясненням у звіті про помилки. Якщо хочете додати нові синоніми (наприклад,
власну назву колонки з вашого щоденного файлу постачальника) — допишіть їх у
масив `FIELD_SYNONYMS` у `ImportExport.gs`.

## Нове: дві ціни постачальників (EUR)

У кожного товару тепер два поля цін замість однієї закупівельної ціни:
- **Ціна — місцевий постачальник (EUR)**
- **Ціна — німецький постачальник (EUR)**

Обидві бачить лише роль **Admin** (як і раніше з ціною). При імпорті Excel
вони підтягуються з відповідних колонок файлу (див. вище).

## Нове: «Вироби» (специфікація складу / BOM)

Розділ **"🛠 Вироби"** дозволяє описати готовий виріб як набір товарів зі складу:

1. Створюєте виріб, вказуєте назву.
2. Додаєте компоненти — обираєте товар зі списку складу та кількість,
   потрібну **на одну одиницю** виробу.
3. Собівартість виробу рахується автоматично й одразу (для admin) — окремо
   за місцевими цінами і окремо за німецькими, в євро.
4. Коли потрібно зібрати вироби — відкриваєте картку виробу, вказуєте
   **скільки одиниць** зібрати, і натискаєте **"▶ Дати в роботу"**.
   Система перевіряє, чи вистачає всіх компонентів на складі (все або
   нічого — якщо хоч одного не вистачає, списання не відбувається), і
   якщо все ок — автоматично списує потрібну кількість кожного компонента
   зі складу та записує операцію в історію разом з підсумковою собівартістю.

Створювати/редагувати вироби та запускати їх у роботу можуть **Admin** і
**Комірник**; видаляти виріб повністю — лише **Admin**.

## Розгортання (5–10 хвилин)

1. Перейдіть на **script.google.com** → **"Новий проєкт"**.
2. Назвіть проєкт, наприклад, `SHSklad`.
3. Видаліть стандартний вміст `Code.gs` і послідовно створіть усі файли з цього
   проєкту (кнопка `+` → `Сценарій` для `.gs`, `+` → `HTML` для `.html`),
   скопіювавши вміст кожного файлу один-в-один (включно з назвою файлу — без
   розширення, наприклад файл `Style.html` створюється як HTML-файл з іменем `Style`).
4. Відкрийте `appsscript.json` через **"Налаштування проєкту" → "Показати файл
   appsscript.json у редакторі"** і замініть вміст на файл з цього проєкту.
5. Збережіть проєкт (Ctrl/Cmd+S).
6. У редакторі виберіть функцію **`setupDatabase`** у випадаючому списку зверху
   і натисніть **"Запустити"** (перший запуск попросить надати дозволи —
   підтвердіть). Це створить Google-таблицю `SHSklad_DB` з усіма аркушами і
   стартовими користувачами, а також папку `SHSklad_Photos` на Google Drive.
7. Натисніть **"Розгорнути" → "Нове розгортання"**:
   - Тип: **"Веб-застосунок"**
   - Виконати від імені: **"Я"**
   - Хто має доступ: **"Будь-хто"** (або "Будь-хто в організації" — залежно від потреби)
8. Натисніть **"Розгорнути"**, скопіюйте посилання на веб-застосунок — це і є
   готовий SHСклад, який відкривається в будь-якому браузері, зокрема Safari на iPhone.
9. (Рекомендовано) Додайте посилання на головний екран iPhone через
   Safari → "Поділитися" → "На екран «Домівка»" — застосунок відкриватиметься
   на весь екран, як нативний.

## Де зберігаються дані

- **Товари, користувачі, історія, одиниці виміру** — Google-таблиця `SHSklad_DB`
  (створюється автоматично, ID зберігається в Script Properties).
- **Фото товарів** — папка `SHSklad_Photos` на Google Drive власника скрипту.
- **QR-коди** — генеруються на льоту через безкоштовний сервіс `api.qrserver.com`
  (посилання зберігається в таблиці, файли не завантажуються на Drive окремо).
- **Резервні копії** (Налаштування → "Створити резервну копію") — повні копії
  таблиці `SHSklad_DB` з міткою часу, зберігаються поруч на Google Drive.

## Особливості реалізації

- **Сесії** — токен зберігається в `CacheService` (8 годин) і в `sessionStorage`
  браузера, тому оновлення сторінки не вимагає повторного входу.
- **QR-коди** — кодують `SHSKLAD:<артикул>`. Сканування камерою відбувається
  прямо в браузері через бібліотеку `jsQR` (без зовнішніх застосунків).
- **Excel** — розбір і генерація `.xlsx` відбувається на клієнті бібліотекою
  `SheetJS`, сервер працює з готовим JSON — це найнадійніший підхід у межах
  можливостей Google Apps Script.
- **Історія** — записи в аркуші `History` ніколи не видаляються програмно.
