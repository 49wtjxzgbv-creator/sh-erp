# SH ERP — виробничий та складський облік для реального бізнесу

**SH ERP v2** — мультитенантна SaaS-система управління виробництвом, складом, закупівлями та продажами. Повний перепис попередньої версії (Google Apps Script + Google Sheets) на сучасний стек: NestJS + Next.js + PostgreSQL + Prisma.

Продукт компанії Shyring. Статус: **production-ready**, готовий до першого запуску на реальному сервері.

## Що вміє система

- **Виробництво** — виробничі замовлення повного циклу: резервування матеріалів, стадії виконання, серійні номери готової продукції, контроль якості (QC).
- **Склад** — облік залишків у реальному часі, переміщення між складами, інвентаризації з розбіжностями, повна історія рухів.
- **BOM** — багаторівневі специфікації з версіонуванням, автоматичний розрахунок собівартості, перевірка доступності компонентів.
- **Закупівлі** — постачальники, замовлення на закупівлю, приймання товару з автоматичним оновленням залишків.
- **Продажі** — замовлення клієнтів, відвантаження, автоматичний розрахунок дефіциту з пропозиціями на закупівлю.
- **HR та зарплата** — співробітники, відрядна оплата праці, звірка з результатами контролю якості.
- **Звіти** — рекомендації щодо поповнення запасів, оцінка вартості складу, щомісячні виробничі підсумки.
- **AI-асистент** — розпізнавання рахунків постачальників, голосові команди, підказки з обов'язковим підтвердженням критичних дій людиною.
- **Excel-імпорт/експорт, друк документів** (пік-листи, специфікації, накладні, етикетки).
- **Гнучкі ролі та права доступу**, повністю кастомізовані для кожної компанії.
- **Super Admin** — окрема глобальна панель для оператора платформи: перегляд усіх компаній, вхід у будь-яку компанію, керування тарифами, блокування компаній, глобальний журнал дій. Повністю відокремлена від звичайної авторизації компаній (окрема роль, окремий JWT, окремий журнал).

## Технологічний стек

| Шар | Технологія |
|---|---|
| Backend | NestJS, TypeScript, Prisma ORM |
| Frontend | Next.js 14 (App Router), React, Tailwind CSS |
| База даних | PostgreSQL 16, Row-Level Security для ізоляції даних компаній |
| Файлове сховище | Cloudflare R2 (presigned upload/download) |
| Автентифікація | JWT з ротацією refresh-токенів, argon2id |
| i18n | next-intl (українська — основна, англійська/польська/німецька) |
| AI | Google Gemini (через провайдер-абстракцію, легко замінити) |

Ізоляція даних кожної компанії забезпечена подвійно: на рівні застосунку (Prisma Client Extension) і на рівні самої бази даних (PostgreSQL RLS) — див. `docs/adr/0002-multi-tenant-shared-schema-rls.md`.

## Структура репозиторію

```
backend/            NestJS API (12 модулів — Tenancy, Identity, Catalog, Inventory,
                     BOM, Production, Procurement, Sales, HR, Reports, AI, Notifications)
frontend/           Next.js застосунок: публічна Landing Page ("/"), /login, /register,
                     авторизована частина (app/(app)/), окрема Super Admin панель (app/super-admin/)
prisma/             Єдина схема БД (schema.prisma, 50 моделей) + міграції — спільні
                     для backend і migration-toolkit
migration-toolkit/  Інструментарій перенесення даних зі старої системи (v1) у v2
ops/                Скрипти розгортання: deploy.sh (повністю автоматичний деплой),
                     systemd-юніти, конфігурації Nginx, налаштування чистого сервера
docs/               Уся документація проєкту (див. нижче)
```

Файли `.gs`/`.html` у корені репозиторію — це **стара система (v1)**, Google Apps Script. Вона не видалена, а зберігається як джерело істини для бізнес-логіки під час міграції клієнтів на v2 (детальніше — розділ нижче).

## Розгортання

Продакшн-розгортання на чистому Ubuntu Server повністю автоматизоване одним скриптом:

```bash
git pull
./ops/deploy.sh
```

Скрипт сам виконує: встановлення залежностей, `prisma generate`/`migrate deploy`/`db seed`, збірку backend і frontend, перезапуск обох systemd-сервісів та перевірку, що все працює — без жодної ручної команди. Повна інструкція — у [`docs/deployment.md`](docs/deployment.md).

## Локальна розробка

```bash
# Backend
cd backend && cp .env.example .env   # заповніть DATABASE_URL, JWT_ACCESS_SECRET
npm install && npm run prisma:generate && npm run prisma:migrate:dev
npm run start:dev                     # http://localhost:3000, Swagger: /api/docs

# Frontend (окремий термінал)
cd frontend && cp .env.example .env.local
npm install && npm run dev            # http://localhost:3001
```

Докладніше — у `backend/README.md` та `frontend/README.md`.

## Стара система (v1)

До перепису SH ERP існував як застосунок на Google Apps Script + Google Sheets (база даних) + Google Drive (фото) — повністю робочий, використовувався реальними клієнтами. Його вихідний код (`.gs`/`.html` файли в корені репозиторію) збережений і не видалений: під час міграції клієнта зі старої системи на v2 саме він є джерелом істини щодо бізнес-логіки.

Повний опис старої системи — у файлі **`SH ERP v1 — System Documentation.md`**. Інструкція з перенесення даних конкретного клієнта — [`docs/migration.md`](docs/migration.md).
